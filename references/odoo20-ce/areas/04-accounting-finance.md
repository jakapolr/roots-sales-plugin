## 3. Feature deep-dive

### 3.1 What CE actually contains (the "Invoicing" app)
[code] `addons/account/views/account_menuitem.xml` defines the top menu **Invoicing** (`menu_finance`) with: Dashboard (journal kanban); Customers (Invoices, Credit Notes, Payments, Products, Customers); Vendors (Bills, Refunds, Payments, Products, Vendors); Accounting (Transactions: Journal Items, Analytic Items; empty "Closing" folder that Enterprise fills); Review (Journal Items); Reporting (Invoice Analysis, Cashflow Analysis, Analytic Report; empty folders "Statement Reports", "Partner Reports", "Taxes & Fiscal"); Configuration (Settings, Chart of Accounts, Taxes, Journals, Currencies, Fiscal Positions, Multi-Ledger, Tax Groups [debug], Cash Rounding, Payment Terms, Incoterms [debug], Product Categories, Analytic distribution models/accounts/plans).

Present in CE: customer/vendor invoicing, credit/debit notes, payments + register payment wizard, early payment discount, payment terms, taxes (incl. price-included, fixed, group, python via module, CABA), fiscal positions, analytic accounting, cash rounding, lock dates + lock exceptions, bank/cash journals and bank statement + statement lines (`account.bank.statement[.line]`, actions `action_bank_statement_tree`), reconcile models (`account.reconcile.model` with `rule_type`, `payment_tolerance`), multi-currency, multi-ledger (journal groups), inalterable hash/secure entries, Peppol/UBL e-invoicing, online payment, QR codes, batch sending (`account.move.send` wizards), vendor-bill autopost, accrued orders wizard, partner merge, hierarchical chart of accounts, the **report data model** (`account.report`, `.line`, `.expression`, `.column`; `addons/account/models/account_report.py`) with only a Generic Tax report seeded (`data/account_reports_data.xml`, 18 records).

Enterprise-only / not in this repo [code, by absence]: the **bank reconciliation widget** (journal-create wizard is referenced as `account_accountant.action_journal_create_wizard` in `views/account_journal_views.xml:216`; no reconciliation client component in `account/static/src/components`), full financial reports UI (P&L, balance sheet, trial balance, aged, general ledger: models exist but there is no report renderer/client action; Settings still has `module_account_accountant`, `module_account_budget`, `module_account_intrastat`, `module_account_avatax`, `module_account_batch_payment`, `module_account_iso20022`, `module_account_sepa_direct_debit`, `module_account_bank_statement_import_qif`, extract/digitization modules in `models/res_config_settings.py`), assets/depreciation, budget, loans, fiscal-period/closing UI (`use_fiscal_periods`, `enable_snapshots` fields exist on `account.report` as engine hooks). Note `module_account_reports` was removed from settings in 20 (field gone) — reports are folded under `account_accountant` in the settings UI [Medium: inferred from removal of the field].

### 3.2 Chart of accounts: groups replaced by parent accounts (coordinator's priority item)
Verification of the web summary:
- "Parent accounts replace account groups" — **TRUE** [code, High]. v19 had `account.group` (`code_prefix_start/end`, `parent_id`, `company_id`) and `account.account.group_id` computed by prefix (`odoo19/addons/account/models/account_account.py:113,437`, `_order='code_prefix_start'` at :1517), loaded via template model list `'account.group'` (`odoo19/addons/account/models/chart_template.py:24`) plus an `account.group-*.csv` per CoA (e.g. `odoo19/addons/l10n_do/data/template/account.group-do.csv`). In v20 the model is gone from `account` (no `account.group` field/model; `models/account_account.py` has `_parent_store = True`, `parent_id` Many2one to `account.account`, `parent_path`, `parent_ids`, `code_path`, `name_path` at lines 30, 133-142, 46-62). Account display name for users with readonly group uses `name_path` (`:924`). Ordering is `code_path, account_type, name_path` (`:29`). The chart-of-accounts list uses a new JS view `account_hierarchy_list` (`static/src/views/account_account_list_view`), form shows "Parent Account" (placeholder "Root account"; `views/account_account_views.xml:72`).
- Migration of templates: group rows became **inactive parent accounts** in the account CSV with a `parent_id` column: `l10n_do/data/template/account.account-do.csv` header `"id","parent_id","active","code","name","account_type",...` with rows `account_group_1,...,"False"` (inactive); same in `l10n_ua`, `l10n_ar`, `l10n_mz`, and 10+ other l10n CSVs (`grep -l parent_id l10n_*/data/template/account.account-*.csv`). Generic `chart_template.py` gained `_get_account_parent_xmlid` / `_get_account_parent_id(code_prefix)` hooks (lines ~860-875) used when creating bank/transfer accounts, so new bank accounts can be attached under a parent. Parent accounts need an `account_type` (required field), which is why imported group rows carry types like `asset_non_current`.
- "Account codes become optional" — **NOT supported by code** [code, Medium]: `code` is still non-required (as in v19) and only regex-checked when set (`_check_account_code`, `:288-291`); but v20 makes it `compute_sql`-backed and company-dependent via `code_store` (same as 19). No evidence of a new "optional code" change. Parent accounts still carry codes in templates.
- "Depreciation models replace asset models" — **not verifiable in CE** [code]: CE has no `account.asset` model or asset module; the only asset artefacts are template CSVs `l10n_th/data/template/account.asset-th.csv` (present in both 19 and 20, loaded by Enterprise `account_asset`). `expense_depreciation` account type exists. Treat as Enterprise-side / [web-unverified].
- Reports grouping: `account.report.line` lost `foldable` -> `foldability` (selection), `account.report` lost `prefix_groups_threshold` and `filter_analytic`, gained `groupby/user_groupby`, `active_selection/active_fallback`, `filter_line_comparison`, `enable_snapshots`, `use_fiscal_periods`. `spreadsheet_account/models/account.py` still defines `get_account_group` (:195) — now based on account types (check before use in custom spreadsheets). Anything in customisations referencing `account.group`, `account.account.group_id`, `code_prefix_start`, `account.group` ir.rules (`account_group_comp_rule` removed from `security/account_security.xml`) breaks. `account.tax.group` lost `tax_payable_account_id`, `tax_receivable_account_id`, `advance_tax_payment_account_id` (moved elsewhere; not located in CE — Medium/Low).
- Thai CoA (`l10n_th`): template files are `account.account-th.csv`, `account.asset-th.csv`, `account.tax-th.csv`, `account.tax.group-th.csv`, `account.fiscal.position-th.csv` in v20 (no `account.group` CSV in either 19 or 20 for th, so there is no group-to-parent conversion to do for Thai; the CSV has no `parent_id` column — flat chart; partners can add parents manually). For a Thai customer migrating from 19, nothing is lost, but account-group-based report lines/spreadsheets would need re-pointing.

Test official upgrade scripts: `account/migrations/1.5/pre-migrate.py` only fixes `code_store = 'null'` — the large schema moves are mainly handled by the OpenUpgrade-style upgrade service (not visible in CE; Low/unknown).
